## Scope and acceptance

Radicle is the native plugin backend for PluginTool and GardenEngine. Semantic support is classified separately as READ / WRITE / ADD / REMOVE / CREATE / REMAP / VALIDATE / OPAQUE. A decoder may land independently; it does not establish editing parity.

An editable surface must pass parse -> expose -> edit -> serialize -> reparse, including requested values, valid insertion/removal structure, master/reference remapping, rejected malformed writes, untouched fields and opaque bytes, and file save/reload. A serializer preserving an unmodified record proves preservation, not field interpretation or editing.

xEdit definitions, official plugin measurements, existing typed implementations, CK/CKRE and synthetic tests may establish stored layouts. Runtime RE is required for unresolved stored layouts, unproven safe mutation or actual runtime behavior. Evidence priority does not make executable RE a universal prerequisite. Unknown layouts remain opaque or reject mutation/remapping.

### Unsupported or opaque (not attributable by the script)

- Semantic letters (READ, WRITE, ADD, REMOVE, CREATE, REMAP, VALIDATE, OPAQUE) are not derived; see the hand-kept section below the table.
- Row counts are not compared with xEdit members. The script does not enumerate xEdit members, so unlisted members, enums, flags and structs are not attributed.
- Schema kinds are `scalar`, `string` and `counted_array`. A counted array has no row of its own: `scalar_rows` expands it into its member scalar rows (stride addressing), and its count subrecord is a scalar row. Enum and flags fields are scalar rows with an `enum` or `flags` presentation that carries xEdit names; other struct fields have no kind and are absent.
- Dedicated PluginEditTool routes are not derived, so the tier stops at schema, typed module and remap evidence (no L5).
- Typed module attribution is the `TYPED_MODULES` map in this script. The script checks that each cited file names the signature, but not that it still reads the record semantically.
- Subrecord-level remap handlers apply to any record carrying the subrecord and are not attributed to a record: OBTS (`obts_formid_offsets`, called from `src/schema/form_links.cpp`) and the behavior handlers in `src/schema/behavior_layout.cpp`.
- Mixed remap is attributed only by a record signature named in `src/schema/form_link_mixed.cpp` or `src/schema/form_link_records.cpp`. Record-specific checks in `src/schema/form_links.cpp` (IPDS PNAM, DOBJ DNAM, CLMT WLST) and the generic remap tables (`formid_subrecords.inc`, `structured_formids.inc`) are not counted, so those records can be remapped correctly and still show no mixed remap.
- VMAD (`src/schema/vmad.cpp`, `src/forms/quest_vmad.cpp`) has no field rows and is not attributed to any record.
- Localized subrecords are counted by name in `localized_subrecords`; the generated localized table is not compared with them.
- Real-data tests are counted when a registered `tests/*_real.cpp` names the signature in quotes. A test that covers a family without naming the signature is not counted. Presence is not a pass result; no CI result is read.
- TES4 and records outside `src/forms` and `src/environment` (for example `src/plugin/tes4.cpp`) have no typed module in this script.
