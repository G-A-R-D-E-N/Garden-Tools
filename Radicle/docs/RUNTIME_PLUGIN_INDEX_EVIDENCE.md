| Operation | OG 1.10.163 address | AE 1.11.240 address | Verified behavior |
|---|---|---|---|
| Add to collection | `0x1158c0` | `0x2e6dc0` | Append to separate full/light arrays, assign position starting at zero |
| Full rebuild | `0x116c20` | `0x2e8020` | Walk checked files in supplied list order, active file last, skip existing entries |
| Header classification | `0x12ed70` | `0x2f5eb0` | Header bit `0x200` or case-insensitive `.esl` extension makes the file light |
| Runtime ID conversion | `0x131fa0` | `0x2f91c0` | Light slot occupies bits 12 through 23 under the FE marker |

`build_runtime_form_id_context` already partitions its caller's ordered plugins into independent tables. It now recognizes the verified extension rule as well as the header flag. It leaves stored TES4 flags untouched and reuses `PluginKey::looks_light`. The input must be the caller's enabled, resolved load order, including any active-file positioning. Radicle does not parse Plugins.txt, invent checked/active state, reorder masters or deduplicate silently. Tests cover the extension-only file, flagged `.esm`, independent slot numbering and unchanged header, alongside existing duplicate and overflow refusal tests.

The note finds the same assignment structure in NG 1.10.984. Its unpacked image matches AE 1.11.240 by instruction comparison (#520 comment 13470, RE-006 Q2, evidence commit 78e013b2, `RE-Work/subsystems/plugin-io-garden-tools/small-file-compile-index-389/` and `RE-Work/subsystems/radicle-re-garden-tools/light-plugin-index-389-28/`): rebuild (NG `0x294110` / AE `0x2e8020`, 220 of 220 instructions), TES4 header reader (NG `0x2a1950` / AE `0x2f5eb0`, 391 of 391), archive predicate (NG `0x158de70` / AE `0x16a8d60`, 56 of 56) and register routine (NG `0x158e110` / AE `0x16a9000`, 21 of 21) are equal. The scan driver differs only in one test mask (`0x3fffffff` vs `0x1fffffff`), with no effect because bit 29 is never set. No medium/update distinction, additional reserved slot or collection-site limit check was found in the inspected paths; this is not proof of absence throughout the engine. Radicle retains its explicit 254 full / 4096 light caps and duplicate refusal rather than reproducing truncation or wrap.

The 6916afb follow-up is available locally at `light-plugin-index-389-28/README.md` (not committed). Its OG `0x117d80` / AE `0x2e9020` assembly and OG `0x116460` / AE `0x2e78a0` master-hoist records establish file-list construction statically for those two builds. The hoist applies to master-flag dependents; it is not a general topological sort of plain ESP dependencies. Checked state comes from official/CC presence, enabled Plugins.txt entries, test-file settings and recursive master checks. NG was compared by instruction against AE, as above. External limits and live behavior for reordered or cyclic dependencies remain unresolved.

This evidence does not require Radicle to discover the runtime list when editing stored plugins. `build_runtime_form_id_context` continues to require caller-supplied resolved order; automatic list construction and runtime reproduction remain separate #389 work. Stored master/form ID editing is judged by its remap and serialization tests, not by completion of those runtime questions.

Address correction: OG 1.10.163 uses `0x131fa0`; `0x131f90` belongs to the older 1.10.155 image. The existing build-identification record in `OPEN_QUESTIONS.md` explains the two PE timestamps. Do not treat this as a universal symbol-table shift. The original evidence update had CI validation only; current integration validation is recorded separately in the PR description.
