# Stored package, combat-style and idle editing

This #345 slice reads and edits stored PKDT, PSDT, PKCU version/template, scoped package links, location/target fields, combat-style values, and idle selection data and strings. It does not schedule or execute NPC behavior. [RE #407](https://git.nomadicinteractive.dev/GARDEN/GARDEN-TOOLS/issues/407) contains static OG findings and the remaining questions. The procedure tree and data-input structure are decoded (see Procedure tree), data-input values are typed for Bool, Int and Float and located by subrecord for the other kinds, and data inputs can be added, set and removed. Leaf payloads and VMAD fragments remain opaque.

## PACK

The newer [verified runtime record](https://re.nomadicinteractive.dev/ReverseEng/Fallout4_Runtime_Research/src/commit/6916afbcbec8ab09ecc0dfd30661502d0064f4f7/RE-Work/subsystems/radicle-re-garden-tools/packages-combat-idle-407-345/README.md) supersedes the older missing-layout index. Q1 stamps the OG loader at address 0x719180 and schedule consumer at 0x71EC30.

PKDT is 12 bytes: u32 general flags, u8 type, interrupt override, preferred speed and unknown byte, u16 interrupt flags and an unnamed trailing u16. These are raw stored compatibility fields. The runtime uses that interpretation from form version 0x15; older forms follow a legacy path that forces effective preferred speed to 2. This reader still returns the stored byte, without claiming that effective value. PSDT is 12 bytes: signed bytes month, weekday, date, hour and minute, three unused bytes, then unsigned u32 duration in stored minutes. These stored values are returned unchanged. The reader does not apply the runtime's pre-version-122 month adjustment, defaults, or schedule evaluation.

PKCU is 12 bytes: u32 data-input count, package-template form ID and u32 version counter. CNAM combat style and QNAM owner quest belong to the prelude before PKCU; later CNAM values are not mistaken for a record-level link. Only prelude CTDA/CIS lists are decoded with the existing condition model. POBA, POEA and POCA are empty on-begin/end/change markers, each with an optional four-byte INAM idle link in its own scope. All remaining post-PKCU subrecords are exposed as ordered opaque signature/payload views, including procedure and data-input condition lists, instead of flattening them into the top-level conditions. Duplicated known markers and malformed known sizes fail closed.

Template link rule (RE-015 Q7, #520 comment 13393, evidence commit 9c47a1c9, `RE-Work/subsystems/radicle-re-garden-tools/packages-combat-idle-407-345/`): instance packages have PKDT type 0x12 and template packages have 0x13. The link routine is OG `0x7203c0` (id 1265998; NG `0x70c650` and AE `0x7600d0`, id 2211781). It links the PKCU template only when the target is a PACK whose own PKDT type is 0x13; the instance's own type is never read. If the instance version is below the template's, the tree pointer is taken as 0; otherwise it is the template's tree. A rejected target leaves the instance with no template and no tree. The constructor `0x71fff0` builds an own tree only when the PKCU template is 0. Of 4,890 shipped PACKs, 4,676 are linked: all are PKDT 0x12 with no tree, all targets are PKDT 0x13, and 4,675 equal their template's version while 1 is above it. The 121 PKDT 0x13 packages are all unlinked and carry a tree.

Q4/Q5 verify PLDT/PTDA constructors at OG addresses 0x726520/0x729300.
The disk compatibility reader accepts PLDT 8/12/16 stored bytes: signed i32 type at 0, raw u32 value at 4,
optional signed i32 radius at 8 and optional collection-item index at 12. PTDA accepts 12 bytes:
signed i32 type, raw u32 value and i32 count-or-distance. Each view carries its original
record subrecord index. PLDT types 0/1/4/6 and PTDA 0/1/3/7 resolve the value
as a form ID; other supported variants keep it numeric. All stored values,
including unused nonzero fields, stay unchanged. Unknown types/shapes receive
no typed view and retain their raw bytes. These views do not claim ownership
by a particular data input or procedure. The procedure-tree reader in the
next section reports boundaries separately and leaves these views unchanged.

## Procedure tree

`decode_package_procedure` (Radicle/src/environment/package_procedure.cpp) reads the subrecords after PKCU without changing `Package::opaque` or the writers. It is exposed as `radicle_package_procedure_decode` with `radicle_package_procedure_free`. The grammar and boundaries come from [RE #407](https://git.nomadicinteractive.dev/GARDEN/GARDEN-TOOLS/issues/407) comments 7894 and 9746 (OG 1.10.163 evidence); the result is a stored-structure view, not a runtime evaluation.

- Data inputs: each is an ANAM whose zstring is a registered input type (Bool, Int, Float, Ref, Location, LocWrapper, LocationSelector, TargetSelector, ObjectList, SingleRef, Topic) followed by exactly one value subrecord, whose tag and size must match that type's stored layout or the package does not decode. The layouts are Bool CNAM 1 byte, Int CNAM 4 bytes (raw dword, signed display), Float CNAM 4 bytes IEEE-754, Ref CNAM 4 bytes, SingleRef and TargetSelector PTDA 12 bytes or legacy PTDT 16 bytes, Location and LocationSelector PLDT 16 or 12 bytes, LocWrapper none, ObjectList CNAM 4 bytes, Topic PDTO 8 bytes or TPIC 4 bytes. Then one UNAM u8 per input, in input order, is that input's id byte; ids are unique but neither contiguous nor ordered (only 246 of 4,887 records have id equal to position, the most common shape is 1, 3, 5, 7), so an id is a key and never a position. An older shape with a BNAM string and a 4-byte PNAM after each UNAM is also accepted. The optional XNAM u8 that closes the list is the Creation Kit's next-id counter: not a count and not derivable from the ids. PKCU[0], the u32 at offset 0, must equal the number of ANAM groups. In shipped data the BNAM and PNAM triples come after the tree instead: no pre-tree UNAM carries a BNAM (0 of 46,174), and all 3,100 UNAM, BNAM and PNAM triples follow the tree. RE-015 (#520 comment 13144) identifies them as the template input-name table. The reader consumes that table after the tree and does not expose it.
- Input edits: `add_package_data_input`, `set_package_data_input` and `remove_package_data_input` (Radicle/src/environment/package_procedure.cpp), exposed as `radicle_package_input_add`, `radicle_package_input_set` and `radicle_package_input_remove`, follow the Creation Kit save order: a new ANAM plus value group goes after the last group, its UNAM at the end of the id run, PKCU[0] is incremented and XNAM is set to the next free id after the new one (wrapping to 0 before 0xFF and skipping ids already in use). Removal deletes the group and its UNAM, decrements PKCU[0], leaves the remaining ids gapped and does not touch XNAM, and is refused when PKCU+4 is 0, because such a package carries a procedure tree whose leaves bind to inputs by id byte and would silently read the wrong input. TPIC and LocWrapper are refused, a raw payload that carries a form ID must already be in the writing plugin's own master numbering, and every refusal leaves the record unmutated. Evidence for the tags, sizes, id bytes and counter: RE issue 19, evidence under `RE-Work/subsystems/radicle-re-garden-tools/pack-procedure-inputs-602-c8/`. What the ObjectList dword means and the per-leaf payload are not determined, so leaf value editing stays out of scope.
- Topic values (PDTO): byte 0 is a kind field (RE-015 Q4, #520 comment 13392, evidence commit 9c47a1c9). Kind 0: bytes 4 to 7 are a form ID, remapped when nonzero. Kind 1: bytes 4 to 7 are a FourCC dialogue-topic subtype, looked up in a 125-row table (40-byte rows, FourCC at +0; GREE row 118, HELO 88, PFGT 1, CUST 0; a miss gives 0x7D, stored as 0). The subtype reader is OG `0x5a1020` (id 813848); NG `0x5efc10` and AE `0x643900` (id 2207074); the table bytes are identical on all three builds. Shipped data has 15,004 PDTO across the seven masters, all 8 bytes, with bytes 1 to 3 always zero. 324 are kind 1 (265 of 11,751 in Fallout4.esm), all following an ANAM "Topic" data input, with values GREE 171, HELO 152 and PFGT 1. The 14,670 list-item PDTO after INAM in POBA, POEA and POCA are all kind 0 and zero. This corrects comment 13144, which said all shipped PDTO values are zero. The runtime path that picks a topic from the subtype index is not traced.
- Tree: the root ANAM is Procedure, Sequence, Stacked, Simultaneous or Random. Templated packages take their tree from the template (RE 7894; the link rule above is verified), so a templated record normally has no tree of its own.
- Container: ANAM, CITC count with that many CTDA (each with optional CIS1 and CIS2), PRCB (u32 child count, u32 flags), then the children, each opened by ANAM. After the children, one optional PFO2 (PFOR for the legacy form) is consumed. Simultaneous is not special: shipped Simultaneous nodes may have no PFO2.
- Leaf: ANAM Procedure, CITC and CTDA, then PNAM naming a registered procedure. The payload up to the next ANAM, PFO2, PFOR, POBA, POEA, POCA, UNAM or XNAM is an opaque subrecord range. One optional PFO2 or PFOR directly after the payload is consumed as a flag override and is outside the range. Shipped data has it after leaves in any parent. The payload itself is not decoded. Leaf FNAM bit 0 is the success flag: on success the leaf sets the done flag and advances the procedure index (RE-015, #520 comment 13151); whether that ends the package is not traced. PKC2 indices are in the payload; a PKC2 value of 0xFF means no input (RE-015).
- Fallback: any boundary that does not reconcile gives `decoded = false`, no nodes or inputs, and one opaque region from after PKCU to the first POBA, POEA or POCA (or the end of the record).

Registered leaf procedure names in this reader: Travel, Sandbox, Sit, Sleep, Follow, FollowTo, Patrol, UseWeapon, Headtrack, ForceGreet, Activate, HoldPosition, UnlockDoors, LockDoors, Range, Escort, Eat, Find, Flee, Guard, GuardArea, Hover, Orbit, KeepAnEyeOn, Acquire, UseIdleMarker, UseMagic, Wander, Wait and Say. A real-data walk of OG 1.10.163, AE 1.11.240 and NG 1.10.984 (4,890 PACKs each, identical results, 0 fallbacks) found every shipped leaf name inside this list; Sit, Say and Eat are listed but never used by shipped leaves.

`expected_input_count` returns the verified input slot counts per leaf (RE 9746): Travel 8, Sandbox 16, Sit 1, Sleep 1, Follow 6, Wait 2 and Say 5. These describe the leaf, not the package's data-input list; the corpus test records a mismatch count instead of asserting one.

Location and target type names follow RE 7894, and the raw fields stay as stored. PLDT types: 0 near reference, 1 in cell, 2 near package start, 3 near editor location, 4 and 5 resolved from a process search result (never shipped), 6 near linked reference, 7 at package location (unproven: no type-7 arm found, RE-015; never shipped), 8 quest alias, 9 location handle (derived), 10 named special reference, 11 input ID matched against the data-input set (RE-015), 12 near self, 13 entire editor-location cell, 14 alias collection item. PTDA types: 0 specific reference, 1 object id, 2 object type, 3 linked reference, 4 quest reference alias, 5 special reference, 6 self, 7 keyword, 8 alias collection item. Type 4 and 5 meanings, type 7, and the 8 versus 9 split are not proven for the values they carry.

Open items from RE #407: leaf payload meanings, data-input value tags for Float, Int, TargetSelector, Ref, SingleRef, LocWrapper and ObjectList, the template and instance input reconciliation rule (the template link rule above is verified; input reconciliation is not), the runtime choice of a topic from the PDTO subtype index, and how the post-tree input-name table (UNAM, BNAM, PNAM) relates to the data inputs (RE-015). The PLDT corpus check asserts bytes 1 to 3 of each shipped PLDT are zero (the type is a single byte in a 16-byte block per RE 407, while the reader reads it as i32).

## CSTY

CSGD is 12 f32 values in the pinned schema's order: offensive, defensive and group-offensive multipliers; melee, magic, ranged, shout, unarmed and staff equipment-score multipliers; avoid, dodge and evade threat chances. Those three sit at +0x44, +0x48 and +0x4C in the runtime struct (derived mapping; RE-015 does not name which CSGD fields map there) and are fractions in [0, 1] with a constructor default of 0.2, not percents (RE-015). CSME has nine or ten f32 values: attack-staggered, power-attack-staggered, power-attack-blocking, bash, bash-recoil, bash-attack, bash-power-attack, special-attack, block-when-staggered, and optional attack-when-staggered multipliers.

CSRA and CSCV are individual f32 ranged-accuracy and cover-search values. CSCR is 44 bytes: nine f32 values (circle, fallback, flank distance, stalk time, charge distance, throw probability, sprint-fast probability, sideswipe probability and disengage probability), u32 throw-max-targets and f32 flank variance. CSLR accepts three, four or five f32 values: strafe, adjust-range, crouch, optional wait and optional range multipliers. CSFL has eight f32 values: hover chance, dive-bomb chance, ground-attack chance, hover time, ground-attack time, perch-attack chance, perch-attack time and flying-attack chance. DATA is raw u32 flags. Omitted optional values remain absent; arrays keep their actual stored count. No runtime numeric bounds or selection effects are asserted.

Cross-reference (RE 7894, OG 1.10.163). The CSME names above follow xEdit, which calls the attack, power-attack, block-when and attack-when fields "staggered"; the engine's own debug table names the same fields "incapacitated". The CSCR fields circle, fallback, flank distance, stalk time and flank variance (+0xA4 in the runtime struct) are engine-labeled. The floats at +0x8C to +0xA0 are unlabeled by the engine, so the xEdit names for those slots are not confirmed. CommonLib declares +0xA0 as a uint32, and RE-015 confirms it is an integer field; the byte-level check is not repeated here. DATA flag bits: 0x1 (debug label "Dueling", otherwise "Flanking") sets the behavior-graph variable CloseMovement, 0x2 sets FlankingMovement and takes precedence over 0x8, which sets ChargingMovement. 0x10 gates a consumer (0x123E230). 0x4 has no consumer found in a negative scan, and other bits are unnamed. What the graph variables do downstream was not traced.

## IDLE

ANAM is eight bytes: parent and previous form ID links. DATA is six bytes: loop minimum and maximum bytes, raw flag byte, raw padding byte and u16 replay delay. The compatibility API's `GroupSection` name does not establish a runtime meaning for the padding byte. DNAM behavior graph, ENAM animation event and GNAM animation file are strict NUL-terminated stored strings. The existing CTDA model supplies raw conditions and CIS operands. Loop/replay consumers remain unresolved in Q8; their units and selection effects are not invented. Strings follow the existing C ABI Windows-1252 to UTF-8 policy.

Selection semantics (derived from RE 7894; labeled derived, not a runtime test). Candidate root idles come from the actor's idle arrays. An idle must pass its own condition list, and its children are reached only through a parent that passed. A candidate found in the recently played list is dropped. Children are searched depth-first unless flag bit 0x02 is set. The final result is accepted only if flag bit 0x02 is set or the animation event name is nonempty. Loop min and max, replay delay and the other flag bits have no proven consumer here.

## Editing

| Surface | WRITE | ADD / REMOVE | CREATE | REMAP / OPAQUE |
|---|---|---|---|---|
| PACK | Known PKDT bytes, signed schedule bytes, unsigned duration, version/template, scoped combat style/quest/idles, discriminated PLDT/PTDA links/numeric fields and present tails | Stable known fields only; coupled counters/markers refused; unlisted sections refuse additions | Refused | Known link variants remap; numeric lookalikes and unknown bytes preserved; unknown PLDT/PTDA variants refuse strict remap |
| CSTY | All known stored floats and integer slots, including existing optional tails | Required fields cannot be removed; unknown CSMD cannot be added/removed | xEdit required defaults | Unknown CSMD preserved |
| IDLE | ANAM parent/previous, DATA selection bytes/replay delay, stored graph/event/file strings | Optional DNAM/ENAM/GNAM on fully known layouts; condition groups refuse structural edits | Zero ANAM/DATA defaults | Both ANAM links remap; unknown and condition payloads preserved |

Setters use `PluginFile.SetScalar`, `SetString`, `SetFormLink` and `FieldCount`, or their native/C ABI equivalents. Repeated location/target indices retain physical occurrence order, including inactive union variants. `PACK\Idles` indices 0/1/2 are begin/end/change and require all three valid marker scopes. The eight-byte PLDT has no radius and cannot acquire one through a scalar edit. Unknown/discriminator/count fields have no writable schema entry. See `docs/code-notes/radicle-package-writer.md` for exact mutation and refusal boundaries.

## GardenEngine consumer probe

Copy `Radicle/probes/gardenengine/PackageProbe.cs` and `Radicle/probes/gardenengine/package_probe.tscn` into `opencw/tools/`. Build `opencw/OpenCommonwealth.csproj` with `RadicleSourceDir` set to this Radicle checkout. Set `FO4_DATA_DIR` to the installed data directory and `RADICLE_NATIVE_PATH` to the built native library of the matching ABI, then run `--headless --path opencw tools/package_probe.tscn` with the double-precision Godot Mono editor. Exit 0 prints `package_probe PASS` with a one-line JSON summary. Exit 77 prints `package_probe SKIP: FO4_DATA_DIR unset`. Exit 1 prints `package_probe FAIL` with the exception.

The probe loads `Fallout4.esm` only and makes no writes. Records are found by walking `env.WinnersOf`, not by editor ID. Its assertions:

- A PACK winner, the first in plugin order, whose decoded package (`RadicleEnvironment.Package`) has PKDT data (`Data`), PSDT schedule (`Schedule`), a PKCU template (`Counter.TemplatePackage`) that resolves through `env.Winner`, and at least one location (`Locations`) or target (`Targets`) whose form resolves. The probe fails only if no PACK satisfies all four.
- One CSTY winner that decodes through `RadicleEnvironment.CombatStyle`. CSTY has no parent or previous link, so only the decode is checked.
- One IDLE winner that decodes through `RadicleEnvironment.Idle`, whose ANAM parent and previous links each resolve through `env.Winner` when present.

The PASS line carries `Pack`, `PackageDataType`, `Template`, `Locations`, `Targets`, `Conditions`, `Opaque`, `CombatStyle`, `CombatStyleMelee`, `Idle`, `RootProcedure` (the root node name, null for a templated record) and `LeafProcedures` (the leaf procedure names in tree order), as form keys, names and counts.
