# Stored VMAD values

## Editing

| Capability | Supported scope |
|---|---|
| READ / EXPOSE | Leading script names, flags and known scalar values; array/struct counts; existing quest fragment/alias views; the scene phase fragment list (native `read_scene_vmad_extras` only, no C ABI or C# export) |
| WRITE | Existing leading-script object/alias, string, signed integer, finite float and boolean values; existing elements of type 11 through 15 arrays |
| ADD / REMOVE / CREATE | Leading scripts and their properties (every authorable property type, by index); the VMAD payload itself on the record types xEdit gives one; a fragment binding on QUST (an unused stage and stage index), PACK, INFO, SCEN (an unused flag bit), PERK and TERM (an unused fragment index); a scene phase fragment on SCEN (native only, no C ABI or C# export) |
| REPLACE | A whole leading property, including its name, flags and type, and its struct members |
| REPLACE | An existing fragment binding: its script name and its fragment (function) name. QUST bindings are addressed by the `(stage, stage index)` pair, PACK, INFO and SCEN bindings by flag bit, PERK and TERM bindings by fragment index, and scene phase fragments by phase index plus phase flag (native only, no C ABI or C# export); the key, the unknown byte and the fragment extras script data keep their bytes |
| REMOVE | A leading script, a leading property, an existing fragment binding, or an existing scene phase fragment (native only, no C ABI or C# export) |
| REMAP | Existing complete VMAD grammar, including record-specific tails; unsupported properties fail closed |
| OPAQUE | Variable type 6, nonempty type 16, nested struct members, array/struct element edits, fragment and alias script property values, creating a fragment section on a VMAD that has none, unknown versions/formats/tails |

Native `set_vmad_property` addresses the script, property and optional array element by physical index. C ABI `radicle_plugin_set_vmad_*` and C# `PluginFile.SetVmad*` use the same writer. Nullable object targets use the current master context without adding masters. Object padding, unedited values and complete fragment tails survive serialization byte-for-byte. Writer support is limited to versions 5/6 and object formats 1/2.

`set_quest_vmad_fragment` rewrites the script and fragment names of the binding that a quest stage already has, and `remove_quest_vmad_fragment` drops that binding and decrements the fragment count. Both address the binding by the `(stage, stage index)` pair this writer keys the list by, which is what lets a quest that binds one stage twice have one of its bindings renamed or dropped; the stage-only form is kept for the single-binding case and fails closed with a `ScalarError` naming the stage index when the stage is bound more than once, rather than picking one entry. The pair forms are also exported to C as `radicle_plugin_set_quest_vmad_fragment` and `radicle_plugin_remove_quest_vmad_fragment`, wrapped by `PluginFile.SetQuestVmadFragment` and `PluginFile.RemoveQuestVmadFragment`; the stage-only forms stay native only. xEdit declares `Quest Stage` and `Quest Stage Index` as u32 and sorts the list on both (`source:xEdit Core/wbDefinitionsFO4.pas:3993-4001 @93cc0bc5`). `Radicle/src/schema/vmad.cpp:read_quest_vmad_extras` reads the first u32 as a `stage` u16 and an unnamed u16 word, so the writer's pair ignores that word; whether it is zero in shipped quests is UNPROVEN. A key that no binding carries is `binding_missing`, and the fragment script data, the alias list, the other bindings and every byte outside the edited entry are left alone. The fragment script name, the fragment name and the fragment script's properties are the caller's business: a caller that creates a fragment must also create the script entry the game expects, so this writer never invents one.

`add_vmad_fragment`, `set_vmad_fragment` and `remove_vmad_fragment` (native only) author the fragment bindings of the other five xEdit fragment records. A binding is addressed by flag bit on PACK, INFO and SCEN and by fragment index on PERK and TERM, which is the key xEdit reads the entry with. `add_vmad_fragment` inserts the new entry in ascending key order, writes a zero unknown byte (the xEdit `wbUnknown` default), sets the flag bit or increments the u16 fragment count, and refuses a key that is already bound, a key past the record's flag bits, and a record whose fragment section is absent or whose fragment script entry is empty. The caller must ensure the key names a real perk entry point or terminal menu index, because this writer does not decode those lists, and it must create the fragment script entry the game expects.

`add_quest_vmad_fragment` (native only) creates a quest fragment binding. It is addressed by the `(stage, stage index)` pair this writer keys the list by, so a quest that binds one stage twice can still gain a binding and a repeated pair is `already_present`; the caller supplies the stage index, because the CK assigns it and it is not derivable from the payload. The entry is inserted in ascending pair order, its unknown words are zero and its unknown byte is 1 (every vanilla QUST fragment entry carries 1; RE #763 is open), and the u16 fragment count is rewritten from the list length. It refuses a record that is not QUST, a VMAD with no fragment section or with an empty fragment script name, an empty script or fragment name, and any payload the loader refuses.

A `SCEN` VMAD carries a second, independent fragment list after the flagged one: the phase fragments (`Core/wbDefinitionsFO4.pas:4049-4064`), addressed by phase index plus phase flag rather than by a flag bit of the main list. `read_scene_vmad_extras` (native) exposes that list, and `add_scene_vmad_phase_fragment`, `set_scene_vmad_phase_fragment` and `remove_scene_vmad_phase_fragment` (native only) author it: rename or drop an existing entry, or create one at a phase index and flag that is not bound yet, inserted in `(Phase Index, Phase Flag)` order, which is xEdit's `wbStructSK([1, 0])` key. The new entry's unknown byte is the zero xEdit default, the u16 phase count follows the list length, and the flag must set at least one of the two phase bits (`OnStart` 0x01, `OnCompletion` 0x02) and no other. Phase fragments exist independently of the main flag bits: a scene whose flags byte is zero still carries its phase list, and every phase edit leaves the main bindings and the fragment script entry alone. The writers reach that list only through a non-empty fragment script name: `src/plugin/vmad_fragment_edits.cpp:load_fragment_section` returns `binding_missing` for an empty one, the same gate as the main bindings, while `src/schema/vmad.cpp:read_scene_vmad_extras` reads the list whatever the name is.

`add_vmad`, `add_vmad_script`, `remove_vmad_script`, `add_vmad_property`, `remove_vmad_property` and `replace_vmad_property` (native only) author the script list and the property list. Structure edits fail closed: they refuse an unsupported, malformed, truncated or duplicate VMAD, a payload with trailing bytes, a VMAD version or object format the writer does not support, an index out of range, a property the encoder cannot represent, and a record whose type xEdit gives no VMAD. `add_vmad` writes the empty payload xEdit defaults to (version 6, object format 2, no scripts, `Core/wbDefinitionsFO4.pas:3873-3881`) after the EDID subrecord, which is the position every VMAD record's authoring rule order uses. Struct values are authorable one level deep: a struct member of type 7 or 11 through 17 is refused. `replace_vmad_property` reports `unchanged` and leaves the payload untouched when the replacement encodes to the same bytes. Script and property counts are rewritten from the new list length, so they cannot drift from the entries.

VMAD string values are stored and returned as UTF-8, while names keep the Windows-1252 boundary; lengths may change up to 65535 bytes. C# rejects embedded NUL text at the string marshalling boundary. Wrong types, malformed/duplicate VMAD, invalid local object target types and unparsed data refuse mutation before altering payloads. Missing records/indices report absence. VMAD is dynamically addressed rather than registered as a flat W0 scalar field. Whole-record creation/defaults remain governed by each record tranche.
