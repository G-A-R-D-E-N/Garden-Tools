# Managed binding CI

## Radicle/bindings/csharp/Radicle.Interop.Tests/Radicle.Interop.Tests.csproj:PropertyGroup

Restore configuration and lock settings belong to the test project. The previous `Radicle/bindings/csharp/Directory.Build.props` applied locked restore to the dependency-free shipped library, and its committed library lock described only the RID-free graph. At `e4b8785a`, a copied consumer referencing `Radicle.Interop.csproj` restored normally but RID restore and publish for `win-x64` failed with NU1004 under SDK 8.0.424; proof: `build/evidence/rid426-red/results.json`. Folder-wide source configuration also restricted implicit SDK runtime-pack resolution to the test feed. Remove that shared props file and the library lock; retain strict test restore and its package lock. [NuGet's lock-file guidance](https://learn.microsoft.com/en-us/nuget/consume-packages/package-references-in-project-files#locking-dependencies) recommends locking the consuming project rather than shared libraries.

`Radicle/bindings/csharp/tools/run_managed_tests.py:main` additionally restores and publishes a fresh `win-x64` consumer referencing the copied library, without overriding locked mode. It disables SDK runtime/apphost-pack downloads only for this framework-dependent library smoke check; the SDK's reference assemblies suffice to compile both libraries. This keeps the check within the offline package-source requirement and does not claim self-contained Godot export acceptance. The actual GardenEngine reference was traced at `opencw/OpenCommonwealth.csproj:ProjectReference` in its existing `papyrus-b0-20261005` checkout; no downstream files are changed. Run 626 at `77400149` exposed Linux's additional implicit `Microsoft.NETCore.App.Host.win-x64` download with NU1101; the SDK's `ResolveAppHosts` task accepts `EnableAppHostPackDownload=false` independently of `EnableRuntimePackDownload=false`.

The same offline RID regression returned NU1004 with the old shared settings and succeeded after their removal; proof: `build/evidence/rid426-regression/results.json`. A separate fresh consumer using its own official NuGet source also passed ordinary `dotnet restore -r win-x64` and `dotnet publish -r win-x64` without lock overrides or runtime-pack-download changes; proof: `build/evidence/rid426-default/results.json`. That online SDK-pack bootstrap check is distinct from offline CI acceptance. The updated helper passed the RID smoke and all 69 managed tests locally; proof: `build/evidence/pr426-rid-green-local.log`.

`Radicle/bindings/csharp/Radicle.Interop.Tests/NuGet.Config` must also be scoped to tests. An actual source-tree ProjectReference with empty consumer caches exposed NuGet's per-project configuration lookup: the previous parent config still restricted implicit library runtime-pack resolution to the test feed, causing NU1101 on first restore. A later publish could succeed after the consumer warmed those packages, so copied-project acceptance alone was insufficient. The feed config now lives beside the test project, while the helper explicitly supplies its absolute path to all offline smoke/test restores. Direct source-tree acceptance uses the consumer's own package sources: initial restore with empty caches and `win-x64` self-contained publish now both pass without lock or SDK-download overrides. Before/after proof: `build/evidence/pr426-real-reference.json` and `pr426-real-reference-green.json`; offline helper proof: `build/evidence/pr426-rid-green-local-final.log`.

`Radicle/CMakeLists.txt:find_package(Python3)` already requires Python unconditionally near the start of configuration. The later optional lookup does not remove this requirement. No additional managed-block lookup is needed.

## Radicle/bindings/csharp/tools/run_managed_tests.py:main

Every managed CTest execution copies both projects without bin/obj and assigns empty package, HTTP and plugin caches. It verifies the complete feed inventory and SHA-256 hashes against `Radicle/bindings/csharp/packages/manifest.json`, then restores in locked mode using the single local source in `Radicle/bindings/csharp/Radicle.Interop.Tests/NuGet.Config`. The test project's lock file pins the transitive graph and package content hashes. `Radicle/bindings/csharp/global.json` pins SDK 8.0.424; setup uses that same file. No package download or warm-cache fallback exists.

`.github/workflows/native-ci.yml:native-linux` additionally executes this complete managed suite inside a fresh user/network namespace with only loopback enabled for VSTest. An external connection must fail with ENETUNREACH before restore/tests. The SDK, actions and native build are provisioned before this isolated phase; fully offline runner bootstrap is outside this proof. Windows CTest uses the same checked-in feed and empty-cache execution, but OS-level network isolation is proved on Linux.

At baseline `7789f0e09f3976c113fdc260907d333d1662f3b1`, a clean copied-project restore from an empty local feed reproduced NU1101. [CI run 624](https://git.nomadicinteractive.dev/GARDEN/GARDEN-TOOLS/actions/runs/624) at the rehearsal head `46c4cf80e5ffb798454240377bc8344a10c56381` confirmed loopback-only networking and ENETUNREACH, then failed restore with NU1301 because no repository feed existed. Local proof: `build/evidence/managed-offline-before-426/restore.log` and `build/evidence/pr426-linux-offline-red.log`. Missing archives, changed archive bytes and a changed dependency version are independently refused by the fixed helper; proof: `build/evidence/pr426-negative-results.json` and its three logs.

`.github/workflows/native-ci.yml:native-linux` and `native-windows-tests` publish the two exact contexts selected by the repository's main protection rule. Direct main pushes are disabled and the rule is enforced for repository admins. The reopened saved form shows both contexts as Matched and admin enforcement checked; `build/evidence/pr426-protection-saved.txt` records that UI evidence because the API response omits the admin-enforcement field. Before this change, the repository reported zero branch protections. With run 624's Linux check failed and Required, the signed-in owner saw “Some required checks were not successful” and only deferred “Create merge commit (When checks succeed)”; no immediate merge or admin bypass was offered. `build/evidence/pr426-failed-required-merge-gate.txt` and `.png` record this live UI proof. No merge was attempted or scheduled, and the merge API endpoint was not invoked.

`.github/workflows/native-ci.yml:pull_request`, `native-linux` and `native-windows-tests` no longer path-filter PRs or depend on a docs-only gate. The previous trigger ignored docs/tool-only PRs, and the gate could skip both required jobs after a docs-only follow-up. Both contexts now execute for every PR head. Main-push path filters, cross-build conditions and Windows main/manual Debug execution retain their prior behavior; only diagnostic artifact upload retains its existing non-blocking error handling.
