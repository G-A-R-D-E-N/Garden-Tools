# VMAD scalar object support boundary

`Radicle/src/schema/vmad.cpp:read_property` reads scalar object properties in both existing object formats. The typed model does not expose the additional unsigned 16-bit word. Accepting a nonzero word while discarding it therefore makes a lossy projection appear fully supported. The reader now treats that case as `UnsupportedVmadProperty`, using the existing partial-result path. Zero remains the existing local support policy; this does not establish engine validity or that the word has no runtime meaning.

The independently maintained parser at `opencw/third_party/Mutagen/Mutagen.Bethesda.Fallout4/Records/Common Subrecords/AVirtualMachineAdapter.cs:FillObject` in GardenEngine reads the same word into `Unused`, and `WriteObject` writes it back in both formats. Its inspected SHA-256 is `1b0f481207c414b2c1ea87206e9a19ba2aef9c664660bc7c45f10619352e8b32`. This is public parser/model evidence; Fallout runtime meaning remains unverified. CommonLib is unchanged.

`Radicle/src/schema/vmad.cpp:read_vmad_scripts` retains preceding properties and marks the script list unsupported before publishing the affected property. `read_quest_vmad_extras` uses the same scalar reader for fragment and alias-script properties. `Radicle/src/quest/runtime.cpp:quest_runtime_data` and the quest-extra reader describe an unsupported property rather than claiming its type alone caused the refusal.

`Radicle/src/c_api_placed.cpp:build_view` already publishes the reader's unsupported flag as `scripts_unsupported`. GardenEngine's `opencw/Services/CellCompiler.RefNodes.cs:AppendRefMetadata` carries that flag to the compiled reference, and `opencw/OpenCw.Papyrus/Vm/GameSession.cs:AttachReference` refuses unsupported sources before binding or initialization. The change adds no ABI field/version and promotes no evidence gate.

`Radicle/src/schema/vmad.cpp:walk_object` and the remapping walkers remain unchanged. Arrays, nested struct walkers and quest alias headers are outside this scalar typed-reader support check. This is not a general rejection of every opaque word, and it does not change remapping policy.

`Radicle/tests/test_vmad_unsupported.cpp:UnexposedScalarObjectWordsStopTheTypedReader` covers formats 1 and 2 with words 0, 1 and 65535, retained preceding properties, unchanged zero-word FormID/alias values, and exact plugin read/write byte preservation. `Radicle/tests/test_environment_placed.cpp:CApiReportsUnexposedScalarObjectWords` checks the public placed-reference flag and property projection with the same inputs.
