# Package, combat style and idle writers

`Radicle/schema/fallout4/fields.json:PACK`, `CSTY`, `IDLE` use the shared existing-field scalar, string and FormLink writers. Disk layouts and defaults come from xEdit 93cc0bc5a1251936c3c7859eee3150eda12a62d7, Core/wbDefinitionsFO4.pas:4177-4251, 6233-6307, 9646-9671, 10526-10653 and Core/wbDefinitionsCommon.pas:3166-3177. These are compatibility contracts, not runtime execution claims. Unknown PKDT bytes, procedure/data-input payloads and unknown union branches are preserved. PACK input counts and PLDT/PTDA discriminators are not writable fields.

`Radicle/src/environment/behavior.cpp:decode_package` reads PSDT duration as unsigned minutes, PLDT/PTDA discriminators as full signed 32-bit values, and PLDT radius as signed optional data. An eight-byte PLDT retains its known prefix and has no radius; it is never widened. PLDT type 4 is an ObjectID FormLink. Unsupported widths and discriminators remain opaque.

`Radicle/src/schema/behavior_layout.cpp:behavior_field_candidates` scopes PACK CNAM/QNAM to the prefix preceding PKCU or the first ANAM. The ANAM boundary also preserves scalar inputs in incomplete legacy fixtures lacking PKCU. INAM editing requires unique, empty, ordered POBA/POEA/POCA markers and one four-byte INAM per scope. Their shared `PACK\Idles` indices are begin/end/change. This is the layout-specific part the generic discriminator cannot express.

`Radicle/src/schema/behavior_layout.cpp:behavior_field_payload_valid` limits mutation to supported PLDT/PTDA, PKDT/PSDT/PKCU, CSME/CSLR and IDLE ANAM widths. `Radicle/src/schema/field_address.cpp:resolve_field_slots` applies that check before exposing valid slots. Repeated fields retain physical slot indices even when a union branch does not match. Absent optional tails return missing; setters preserve every byte outside their selected field.

`Radicle/src/schema/behavior_layout.cpp:behavior_formid_offsets` is also used by `Radicle/src/schema/form_link_mixed.cpp:mixed_formid_offsets` before signature-only remapping. PLDT/PTDA link branches, PKCU template, scoped package links and IDLE ANAM links are remappable; numeric lookalikes remain unchanged. Unsupported PLDT/PTDA branches, duplicate or malformed PKCU ownership and malformed owned links fail strict remapping transactionally. `Radicle/tests/test_behavior_authoring.cpp:AmbiguousCounterOwnershipRefusesStrictRemapTransactionally` reproduced the duplicate-counter gap before the guard and verifies rollback.

`Radicle/schema/fallout4/fields.json:PACK.authoring` registers stable section anchors and refuses coupled PKCU/XNAM/POBA/POEA/POCA changes. PACK creation is refused because procedure/data-input structure has no complete proven construction contract. Optional additions in an existing record with unlisted sections return unknown order. `CSTY.authoring` creates required fields at xEdit defaults; unknown CSMD is preserved and cannot be added or removed. `IDLE.authoring` creates ANAM/DATA zero defaults and supports optional DNAM/ENAM/GNAM additions on fully known layouts. Condition groups remain opaque to structural authoring.

`Radicle/tests/test_behavior_authoring.cpp:EveryRegisteredFieldRoundTripsAndPreservesOtherPayloadBytes`, `Radicle/tests/test_behavior_writer_c_api.cpp:WritersSaveReparseAndExposeSignedOptionalValues` and `Radicle/bindings/csharp/Radicle.Interop.Tests/BehaviorAuthoringTests.cs` exercise public setters, creation, optional additions/removals and refusals. `Radicle/tests/test_behavior_writer_real.cpp` checks every official behavior record's known order and shapes, then mutates at most twelve records per type per master and verifies all untouched record bytes plus all unedited payload bytes after save/reparse. Official game data is read-only. #408 added these exports at `RADICLE_ABI_VERSION` 32.

`Radicle/bindings/csharp/tools/generate_interop.py:emit_probe` stamps the public ABI version and source declarations on its generated layout probe. Its offsets measure Radicle's own declared C structures, not a closed target. The stamp changes with an ABI bump so review identifies exactly which declarations the regenerated probe measures.

`Radicle/src/environment/behavior.cpp:decode_package`, `decode_combat_style`, `decode_idle` and `Radicle/schema/fallout4/fields.json:PACK/CSTY/IDLE` were rechecked against xEdit `93cc0bc5a1251936c3c7859eee3150eda12a62d7`, `Core/wbDefinitionsFO4.pas:4177-4198,4223-4248,6233-6307,9646-9670,10526-10653` and private RE `6916afbcbec8ab09ecc0dfd30661502d0064f4f7`, [packages-combat-idle-407-345/README.md:Q1,Q4-Q8](https://re.nomadicinteractive.dev/ReverseEng/Fallout4_Runtime_Research/src/commit/6916afbcbec8ab09ecc0dfd30661502d0064f4f7/RE-Work/subsystems/radicle-re-garden-tools/packages-combat-idle-407-345/README.md). The stored fields match; no decoder or writer behavior change was needed during main integration. PSDT duration remains raw disk u32 even though the stamped OG schedule consumer interprets it as signed. CSTY creation follows the xEdit defaults, including DATA zero and avoid-threat 0.8, rather than substituting the different runtime constructor defaults. Unproven runtime meanings, leaf payloads and input reconciliation remain outside the stored-data contract.

`Radicle/src/schema/behavior_layout.cpp:behavior_formid_offsets` remaps PACK IDLA as a form ID array: every four-byte slot is a link and NULL is allowed, per `source:xEdit Core/wbDefinitionsCommon.pas:8651-8653 @93cc0bc5` (`wbArray(IDLA, 'Animations', wbFormIDCk('Animation', [IDLE,NULL]))`), reached from `source:xEdit Core/wbDefinitionsFO4.pas:10572 @93cc0bc5`. A size that is not a multiple of four is refused under strict remap and left unchanged otherwise. `Radicle/src/environment/behavior.cpp:decode_package` exposes the same slots read-only as `idle_animations`, and a size that is not a multiple of four fails the decode.

`Radicle/schema/fallout4/fields.json:PACK\Date` (PSDT offset 2, i8) accepts 0 through 31. xEdit `Core/wbDefinitionsCommon.pas:989-1018` (`wbPACKDateAfterLoad`) and `Core/wbDefinitionsCommon.pas:1405-1438` (`wbPACKDateAfterSet`) clamp Date to 0 through a month maximum of 28 for February, 30 for April, June, September and November, and 31 otherwise, and clamp negatives to 0. The month comes from the sibling Month field, shifted by one when `MainRecord.Version < 122`. Date 0 is the xEdit enum entry `Any` (`Core/wbDefinitionsCommon.pas:7723-7731`, `wbPackageScheduleDayOfMonthEnum`). Radicle refuses where xEdit clamps: a value outside 0 through 31 throws `ScalarError` and leaves the plugin unchanged. The scalar writer validates one descriptor and has no cross-field hook, so the month-dependent cap is not enforced: 29 through 31 in February, or 31 in a 30-day month, are accepted where xEdit would clamp. `Radicle/tests/test_behavior_authoring.cpp:PackScheduleDateRefusesDaysOutsideXEditRange` covers the refusals and a valid day.

`Radicle/src/environment/package_procedure.cpp:add_package_data_input`, `set_package_data_input` and `remove_package_data_input` call the record helpers as `fo4::detail::locate_mutable_record` and `fo4::detail::mark_record_modified`. The file includes `Radicle/src/environment/record_reader.hpp`, which declares `namespace fo4::env::detail`, so a bare `detail::` inside `namespace fo4::env` resolves to that environment namespace and not to the `Radicle/src/plugin/record_edit.hpp` helpers. `using detail::Reader;` in the same file stays unqualified because `fo4::env::detail::Reader` is the intended target.
