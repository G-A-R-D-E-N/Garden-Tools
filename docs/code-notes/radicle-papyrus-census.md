# Effective VMAD measurement

`Radicle/tools/parity/common.hpp:read_order` previously treated a missing input file or a nonempty row without a tab separator as an empty or shortened order. Both `Radicle/tools/parity/main.cpp:run` and `Radicle/tools/parity/writeback.cpp:run` use this reader. Two new input regressions run seven tests and produce three failures before the reader changes: missing files falsely succeed in both `papyrus` and `versions`, and a malformed row falsely succeeds. An empty plugin-path row already fails later and is a negative control. Input open and row-shape validation belong in the shared reader; blank lines and the existing informational first column retain their behavior. Final seven focused tests and all 856 configured CTest cases pass, with 39 optional-data skips. Independent read-only review found no cuts. Ignored red log: `Radicle/build-census/papyrus-input-red.log`; final strict build, focused run and full CTest are in `single-config-guard.log`. This does not add a nonempty-order requirement to the generic parity tools or establish recovery from a mid-read I/O fault.

`Radicle/tools/parity/main.cpp:dump_papyrus` adds the `papyrus` mode to the existing parity CLI. It uses `fo4::env::Environment` winners and `fo4::read_vmad_scripts` for all owner signatures, plus `fo4::read_quest_vmad_extras` for quest fragment and alias counts. Deleted winners are omitted. Partial or malformed decode remains explicit and returns failure, rather than become a complete baseline. This is input measurement for GardenEngine issue #218, not Fallout runtime evidence or an ABI change.

`Radicle/tools/parity/tests/test_papyrus_dump.py` constructs only project-authored plugin fixtures. Their record/group headers follow `Radicle/tests/plugin_bytes.cpp:begin_record` / `begin_group`; the quest trailer follows `Radicle/tests/quest_plugin_fixture.hpp:vmad_extras`. The existing `versions` mode first verifies that each fixture loads. The new-mode checks cover effective overrides and deleted winners, quest fragments/alias attachments, and truncated/unsupported VMAD refusal. No private corpus content is committed.

`Radicle/tools/parity/main.cpp:dump_papyrus` writes one sorted `papyrus.tsv` row per non-deleted winning record carrying VMAD: FormKey, record signature, leading script-list count, quest stage-fragment count, quest alias-binding count and scripts attached to those aliases, separated by tabs. Quest counts remain separate from the leading list, preventing a silent change in the meaning of attached-script measurements. `papyrus_failures.tsv` identifies incomplete records; a nonempty failure set means exit 1 and prevents a complete-baseline claim. Non-quest fragment families and array/struct element semantics are outside these counts. Native call sites and complete event-handler classification still require separate evidence; this export alone does not complete #218.

`Radicle/tools/parity/main.cpp:write` previously ignored output-open/write failures. The new output-failure regression created a directory at the intended report filename and observed exit 0 without the measurement artifact. The shared writer now checks open and close/flush completion, so all parity commands fail explicitly when their artifact cannot be saved. Ignored local red log: `Radicle/build-census/papyrus-output-red.log`.

`Radicle/tools/parity/tests/test_papyrus_dump.py:PapyrusDumpTests` failed all three initial tests on parent `c50ad4d5405e1571113019654b10e3d4a05ca0f1` because the mode was absent. The subsequent output-failure regression failed 1/5 before the writer correction; final focused validation passes 5/5. Full strict MSVC Release build succeeds, and configured CTest runs 856 cases with 817 passed, 39 optional-data skips and zero failures, including generated bindings/layout checks. The truncated QUST test proves refusal through VMAD coverage; it does not independently cover the later extras-reader refusal branch. Ignored logs under `Radicle/build-census/` are `papyrus-red.log`, `papyrus-output-red.log`, `papyrus-green.log`, `full-build.log` and `full-ctest.log`. Independent read-only review found no cuts.

`Radicle/tools/parity/main.cpp:dump_papyrus` was measured against a private MO2 profile using Garden's existing `Mo2ProfileLoader.ResolvePlugins` and `Prepare` to identify inputs. All 653 listed plugins resolve, but loading the unfiltered order fails on a mod record with master index 9 beyond its eight-entry master table. Garden's existing loader retains 652 plugins and reports one refused plugin; that retained population measures 32,028 winning VMAD records across 27 signatures, 26,920 owners with leading or alias scripts, 30,122 leading scripts, 16,522 quest fragments, 8,628 quest alias bindings and 10,420 alias scripts, with zero VMAD decode failures. The sorted report SHA-256 is `f1b24478a22a8c9bf51b912d7f00cf35e5b87dc195930f08e5ac3b0c73b392b3`. These counts describe 652 retained plugins, not complete acceptance of the 653-plugin profile. Ordered paths, per-form records and the export probe remain ignored local artifacts under `Radicle/build-census/`; only non-expressive results are recorded here. Missing native/event census inputs and the refused plugin prevent a complete #218 claim.
