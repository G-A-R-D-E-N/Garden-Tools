# Papyrus fragment census

`Radicle/include/fo4/schema/vmad.hpp:VmadCoverage`: fragment_count measures entries consumed by the existing QUST, PERK, TERM, PACK, INFO and SCEN walkers. SCEN includes its flagged entries and phase entries. fragment_script_count is the nonempty fragment-header script count, separate from leading scripts and quest alias scripts. Both counters are zero unless complete() is true. These are structural decode measurements, not Fallout execution, binding, event-order or compatibility proof. No C ABI layout or version changes.

`Radicle/src/schema/vmad.cpp:scan_vmad`: reuse the current walkers and property validation, without introducing a second VMAD parser or changing accepted shapes. Partial, unsupported and trailing data remain incomplete; no partial counts escape through vmad_coverage.

`Radicle/src/schema/vmad.cpp:walk_flagged_fragments`: the flag byte counts only the bits xEdit defines, so reserved bits add no fragments. PACK counts bits 0-2 (`source:xEdit Core/wbDefinitionsCommon.pas:1724-1742 @93cc0bc5`, `wbScriptFragmentsPackCounter`), INFO counts bits 0-1 (`source:xEdit Core/wbDefinitionsCommon.pas:1704-1722 @93cc0bc5`, `wbScriptFragmentsInfoCounter`), and SCEN counts bits 0-1 (`source:xEdit Core/wbDefinitionsCommon.pas:1744-1762 @93cc0bc5`, `wbScriptFragmentsSceneCounter`). `scan_vmad` passes those widths (3, 2, 2). Before this rule the walker looped over all eight bits.

`Radicle/tools/parity/main.cpp:dump_papyrus`: retain papyrus.tsv's six fields unchanged, including its QUST-only stage fragment column. The additional sorted papyrus_fragments.tsv has four fields: FormKey, record signature, parsed fragment-entry count, fragment-header script count. Every accepted winning VMAD has one row, including zero counts. Deleted/overridden records and refused VMADs retain the existing selection/reporting rules. A write failure or decode refusal returns nonzero.
