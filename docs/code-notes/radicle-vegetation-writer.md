# Vegetation scalar editing

- `Radicle/schema/fallout4/fields.json` (records `GRAS`, `TREE`, `FLOR`) registers 31 existing-only scalar fields, all `presentation: identity`. Layouts follow TES5Edit `wbDefinitionsFO4.pas` (GRAS 9612-9644, TREE 12134-12165, FLOR 12167-12197) and `Radicle/src/environment/vegetation.cpp:decode_grass`, `decode_tree`, `decode_flora`. Edits go through the existing `Radicle/src/plugin/mutation.cpp:set_record_scalar`, which patches in place, reports `unchanged` without touching bytes and clears the record's cached bytes.
- `GRAS\Density`, `MinSlope`, `MaxSlope` (u8 at 0, 1, 2), `UnitsFromWater` (u16 at 4), `UnitsFromWaterType` (u32 at 8), `PositionRange`, `HeightRange`, `ColorRange`, `WavePeriod` (f32 at 12, 16, 20, 24) and `Flags` (u8 at 28) address `GRAS\DATA`. DATA keeps prefix semantics, so no `payload_size` is set: `Radicle/src/schema/scalar.cpp:scalar_field_bytes` returns empty for a field past a short payload, which `set_record_scalar` reports as `subrecord_missing` with nothing changed. Bytes 3, 6, 7, 29-31 and any bytes past 32 are never written.
- `GRAS\UnitsFromWaterType` is capped at 7 because the xEdit enum has eight values. Measured over `Fallout4.esm`, `DLCCoast.esm` and `DLCNukaWorld.esm` (the only official masters with GRAS, 107 records, all DATA 32 bytes) the stored values are 0, 2, 6 and 7. The cap is a schema limit for edits, not a claim about the engine; the reader still returns any stored u32.
- `TREE\TrunkFlexibility` through `TREE\LeafFrequency` are twelve f32 at offsets 0..44 of `TREE\CNAM` in xEdit order. Float bounds are +-1e9 like the PROJ/EXPL/HAZD fields; `Radicle/src/schema/scalar.cpp:encode_scalar` already rejects NaN and infinities (`parse_float`) and a result that overflows f32, so no encoder change was needed.
- `TREE\Spring`, `Summer`, `Fall`, `Winter` and the same four `FLOR\` paths are u8 at 0..3 of `PFPC`. These are stored seasonal values; no runtime meaning is claimed (see `Radicle/docs/VEGETATION.md`).
- `Radicle/include/fo4/schema/scalar.hpp:ScalarDescriptor::payload_size` is an optional exact payload size for embedded fields, set from the JSON key `payload_size` by `Radicle/tools/schema_codegen.py:load_fields` (embedded only, a positive integer, at least offset plus storage width). It is 48 for `TREE\CNAM`, 4 for `PFPC` and 2 for `FLOR\FNAM`. `Radicle/src/schema/scalar.cpp:scalar_field_bytes` returns an empty span (field absent) when the payload size differs, exactly like an embedded field beyond a shorter payload, and does not throw. Reason: `PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp` turns any `ScalarError` into a failure of the whole record-table read and `Radicle/src/schema/preflight.cpp` reports it as an error, while the vegetation loader treats a non-48-byte CNAM as an opaque layout; `Radicle/src/environment/vegetation.cpp:decode_tree` leaves wind unset for it and `decode_flora` rejects a wrong-size PFPC/FNAM separately at decode time. So the grid shows a blank non-editable cell, preflight skips it, and `set_record_scalar` returns `subrecord_missing` with no byte changed (44/52-byte CNAM, 3/5-byte PFPC, 1/3-byte FNAM). The whole-payload wrong-width throw is unchanged.
- `FLOR\Flags` is registered as an embedded field at offset 0 of `FNAM` with `payload_size` 2, not as a whole-payload field. `Radicle/src/schema/scalar.cpp:scalar_descriptor` finds whole-payload fields by subrecord signature alone and `FNAM` means different things on other records, so a whole-payload registration would be returned for any FNAM. Embedded fields are skipped by that lookup and are only reachable by record plus path.
- Refusals (`ScalarError`, bytes untouched): wrong record type, duplicate subrecord, value out of range, unparsable value, NaN/infinity. Record absent gives `record_missing`; subrecord absent, beyond a short GRAS DATA, or of an unsupported payload size gives `subrecord_missing`. Nothing is inserted.
- `Radicle/src/c_api_writeback.cpp:radicle_plugin_set_record_scalar` takes a schema path and a decimal string and delegates to `radicle_plugin_set_record_scalar_at` index 0 (W0, `docs/code-notes/radicle-field-writer.md`). `updated` and `unchanged` map to OK; missing record and missing/short/unsupported-size subrecord map to NOT_FOUND (`record has no such field occurrence, or the field is outside its supported payload layout`); unknown path, null argument, invalid key and every `ScalarError` map to INVALID_ARGUMENT. `Radicle/bindings/csharp/Radicle.Interop/PluginFile.cs:SetScalar` returns false for NOT_FOUND and throws `RadicleException` otherwise; callers pass invariant-culture numbers.
- ABI 17 (`Radicle/include/fo4/c_api.h:RADICLE_ABI_VERSION`) is provisional for this branch: it is the #428 number on top of the PR #404 reader, merged with the W0 exports (#432 was ABI 10). The W0 payload_size, scalar, codegen, C ABI and `PluginFile` code replaced #428's copies in the merge; #428 keeps only its 31 fields, tests and docs. `Radicle/tests/test_c_api_quest.cpp:AbiVersionIsSeventeen` pins the value. Reassign the number from current main before merging.
- Coverage: `Radicle/tests/test_vegetation_edit.cpp:VegetationEdit` (every path, unchanged, short DATA, refused layouts, compressed record, C ABI), `Radicle/bindings/csharp/Radicle.Interop.Tests/VegetationEditTests.cs`, and `Radicle/tests/test_vegetation_real.cpp:VegetationReal.EveryNewScalarPathEditsOfficialRecordsWithoutLosingData` over the official masters (skips without FO4_DATA_DIR). Links, authoring and creation are covered in the next section.
- Not done: no claim about runtime consumption of any of these values; no PTRN, PRPS, VMAD, DEST, PNAM, ATTX, RNAM, FULL or model-string field is exposed as a typed field (they stay opaque or reachable only through the generic subrecord surfaces).

## Vegetation links, authoring and creation (W0 schema, no typed code)

Source: pinned xEdit `build/xedit/wbDefinitionsFO4.pas` and `wbDefinitionsCommon.pas`; every statement below about a layout, a default or a required entry is taken from those files.

- `Radicle/schema/fallout4/fields.json` `formlink_fields`: `TREE\Ingredient` (PFIG) and `FLOR\Ingredient` (PFIG) are nullable; `TREE\HarvestSound` (SNAM, `SNDR`, nullable) and `FLOR\HarvestSound` (SNAM, `SNDR`, not nullable) follow the pinned xEdit lines `wbFormIDCK(PFIG, 'Ingredient', sigBaseObjects)`, `wbFormIDCK(SNAM, 'Harvest Sound', [SNDR, NULL])` (TREE 12134-12165) and `wbFormIDCk(PFIG, ..., [ALCH, AMMO, ARMO, BOOK, INGR, KEYM, LIGH, LVLI, MISC, NOTE, WEAP, NULL])`, `wbFormIDCK(SNAM, 'Harvest Sound', [SNDR])` (FLOR 12167-12197). `LTEX\Grass` (GNAM, `repeated`, `GRAS`, not nullable) is addressed by occurrence index, so `radicle_plugin_set_record_formlink` index n, `radicle_plugin_record_field_count` and `PluginFile.FieldCount` work on it.
- `TREE\Ingredient` lists the 43 `sigBaseObjects` targets of `target_unions` plus `ENCH` explicitly: the pinned xEdit `sigBaseObjects` (line 74) contains `ENCH`, the repo's shared union does not. The shared union was left alone because it also drives CNTO, EXPL and quest items; this is a finding for the owner of that union, not a vegetation decision.
- Target validation is the W0 rule in `Radicle/src/plugin/field_writer.cpp:set_record_formlink_field`: a target owned by the edited plugin must exist there with an allowed signature, a target owned by a master is accepted without a type check (the master record is not loaded), an owner missing from the master table is refused (`FormIdError`, INVALID_ARGUMENT), and NULL is refused for non-nullable fields. After saving, `Radicle/src/graph/check_errors.cpp:slot_targets` checks master targets against the same lists. The PFIG, SNAM, GNAM, TNAM and MNAM payloads are remapped by the global Form-ID subrecord table in `Radicle/src/schema/form_links.cpp:visit_link_offsets`; `Radicle/tests/test_vegetation_authoring.cpp:VegetationAuthoring.LinkSurfacesAreVisibleToTheRemapAndCheckScan` proves the scan sees them.
- `LTEX\Grasses` (`formlink_lists`, GNAM, `GRAS`, `appendable`) exists because adding a GNAM with a real target cannot go through `add_subrecord`: GRAS is the only allowed target type and NULL is not allowed, so there is no provable default for a GNAM. `FormLinkListInsert` appends at the end of the record (GNAM is last in xEdit order, so this keeps the order), and `RemoveSubrecord GNAM n` or `FormLinkListRemove` removes one. `add_subrecord GNAM` is refused with `no_default` on purpose.
- `Radicle/schema/fallout4/fields.json` `authoring` blocks (all `top_level`) list every top-level subrecord xEdit can place, in xEdit order. GRAS: EDID, OBND, MODL, MODT, MODC, MODS, MODF, DATA. TREE: EDID, VMAD, OBND, model group, PFIG, SNAM, PFPC, FULL, CNAM. FLOR: EDID, VMAD, OBND, PTRN, FULL, model group, DEST, DAMC, DSTD, DSTA, DMDL, DMDT, DMDC, DMDS, DSTF, KSIZ, KWDA, PRPS, PNAM, ATTX, RNAM, FNAM, PFIG, SNAM, PFPC. LTEX: EDID, TNAM, MNAM, HNAM, SNAM, GNAM. Required (minimum 1) follows xEdit `SetRequired` or the `cpNormal, True` argument: OBND in GRAS, TREE and FLOR (`wbObjectBounds` in `wbDefinitionsCommon.pas` line 9074 ends in `.SetRequired`), GRAS DATA, TREE CNAM, FLOR FULL (`wbFULLReq`) and PFPC, LTEX MNAM, HNAM and SNAM. EDID is minimum 0 like every other registered record.
- `LTEX\GNAM` is `maximum 65535, uncounted`: xEdit declares `wbRArray('Grasses', wbFormIDCk(GNAM, 'Grass', [GRAS]))`, an array of individual subrecords with no count subrecord, so no count can desynchronise. `KSIZ` and `KWDA` are counted by KSIZ (`wbKeywords`) and are never uncounted; the destructible stage subrecords DSTD, DSTA, DMDL, DMDT, DMDC, DMDS and DSTF are `maximum 255` (the u8 `DEST Count`) and not uncounted either, so a repeated one is `not_authorable`.
- New authoring flag `coupled` (`Radicle/tools/record_schema_codegen.py:load_constraints`, `Radicle/include/fo4/schema/record_constraints.hpp:SubrecordAuthoringConstraint::coupled`, `Radicle/src/plugin/subrecord_authoring.cpp:editable`): a `maximum 1` entry whose presence is tied to a count or to sibling subrecords is refused by add and remove (`not_authorable`) and still takes part in the order and cardinality check. It is set on MODL (removing it would orphan MODT, MODC, MODS and MODF), DEST, KSIZ and KWDA. Without it the W0 rules would let `remove_subrecord KSIZ` leave KWDA without its count. Keyword edits go through the existing `FLOR\Keywords` list, which keeps the counter in step. DAMC, MODT, MODC, MODS, MODF, PRPS, PNAM, ATTX, RNAM, PTRN and VMAD stay plain optional entries: they can be removed, and added only if a default exists.
- Defaults (`default`, all provable from the pinned xEdit): OBND twelve zero bytes (six s16 in `wbVec3Int`, no declared default); GRAS DATA 32 bytes from the declared defaults Density 30, Max Slope 90, Position Range 32.0, Height Range 0.2, Color Range 0.5, Wave Period 10.0 and zero for every other field and the unused bytes (generated as `1e005a00000000000000000000000042cdcc4c3e0000003f0000204100000000`); TREE CNAM 48 bytes with Trunk Flexibility, Branch Flexibility, Leaf Amplitude and Leaf Frequency 1.0 and the other eight floats 0; PFPC four zero bytes (TREE and FLOR, both match the `payload_size` 4 field rows); FLOR FNAM two zero bytes (matches `payload_size` 2); FLOR FULL a single NUL (an empty string, usable only in a non-localized plugin because `Radicle/src/plugin/subrecord_authoring.cpp:default_usable` refuses a default for a localized field; FLOR is now registered with `localized_subrecords` FULL, ATTX, RNAM and TREE with FULL); LTEX SNAM one byte `1e` (u8, xEdit default 30, official size 1), LTEX HNAM `1e1e` (Friction and Restitution u8, both default 30, official size 2), LTEX MNAM `00000000` (`[MATT, NULL]` allows NULL, official size 4); TREE PFIG and SNAM and FLOR PFIG `00000000` because their lists contain NULL. No default for FLOR SNAM and LTEX GNAM (`[SNDR]`, `[GRAS]` have no NULL), TNAM, PTRN, VMAD, PRPS, PNAM, ATTX, RNAM, the MODL group and the DEST group: xEdit gives no layout or no valid empty value.
- `create_record` works for GRAS, TREE, LTEX and (non-localized plugins only) FLOR. A localized plugin refuses FLOR with `no_default` and allocates nothing. Created shapes: GRAS EDID OBND DATA; TREE EDID OBND CNAM; FLOR EDID OBND FULL PFPC; LTEX EDID MNAM HNAM SNAM. All pass `preflight_authoring_record`, save, reload and decode through `decode_grass`, `decode_tree`, `decode_flora`, `decode_landscape_grasses` and the C and C# getters with the xEdit defaults above.
- Official data (Fallout4.esm, DLCCoast.esm, DLCworkshop03.esm, DLCNukaWorld.esm: 107 GRAS, 1 TREE, 64 FLOR, 128 LTEX): every subrecord of every record is listed in its authoring block, and every record satisfies the order and cardinality rules except four FLOR in Fallout4.esm with two destructible stages (`FloraFern01` 000E34EA, `FloraFern02` 000E34EB, `FloraCornStalk01` 000E7744, `FloraCornStalk02` 000E7745). Their stages repeat DSTD with DSTF (and DMDL, DMDT) as a group, and the flat order check has no repeating-group model, so DSTD after DSTF reads as out of order. `add_subrecord` is `unknown_order` on those four (removal and every link or scalar edit still work); the other 60 FLOR, all GRAS, the TREE and all LTEX accept add and remove. `Radicle/tests/test_vegetation_real.cpp:VegetationReal.EveryOfficialRecordIsListedAndOrderedInTheAuthoringSchema` asserts that the violators are exactly the records with more than one DSTD.
- Official-master mutation (`VegetationReal.LinksGrassListsAndOptionalSubrecordsEditOfficialRecordsAndKeepEveryOtherRecordByteIdentical`): TREE and FLOR links are set, the TREE gains PFIG and SNAM (add, remove back to the original subrecords, add again), every LTEX GNAM is set, one GNAM is inserted and removed (back to the original subrecords) and inserted again, FLOR PFPC removal is refused; after save and reparse every record outside the edited TREE, FLOR and LTEX set is byte-identical, and the edited records carry exactly the new links. Fallout4.esm: 159 records, 230 link edits, 107 subrecords added; DLCCoast.esm: 16 records, 25, 8; DLCworkshop03.esm: 1 record, 2, 0; DLCNukaWorld.esm: 17 records, 26, 15. The other three masters have no TREE, FLOR or LTEX and are skipped.
- Tests: `Radicle/tests/test_vegetation_authoring.cpp:VegetationAuthoring` (native links, base-object targets and null, repeated and list GNAM, optional add and remove, creation and decode, localized FLOR, link scan, C ABI statuses with save and decode) and `Radicle/bindings/csharp/Radicle.Interop.Tests/VegetationAuthoringTests.cs`.
