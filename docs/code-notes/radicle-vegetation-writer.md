# Vegetation scalar editing

- `Radicle/schema/fallout4/fields.json` (records `GRAS`, `TREE`, `FLOR`) registers 31 existing-only scalar fields, all `presentation: identity`. Layouts follow TES5Edit `wbDefinitionsFO4.pas` (GRAS 9612-9644, TREE 12134-12165, FLOR 12167-12197) and `Radicle/src/environment/vegetation.cpp:decode_grass`, `decode_tree`, `decode_flora`. Edits go through the existing `Radicle/src/plugin/mutation.cpp:set_record_scalar`, which patches in place, reports `unchanged` without touching bytes and clears the record's cached bytes.
- `GRAS\Density`, `MinSlope`, `MaxSlope` (u8 at 0, 1, 2), `UnitsFromWater` (u16 at 4), `UnitsFromWaterType` (u32 at 8), `PositionRange`, `HeightRange`, `ColorRange`, `WavePeriod` (f32 at 12, 16, 20, 24) and `Flags` (u8 at 28) address `GRAS\DATA`. DATA keeps prefix semantics, so no `payload_size` is set: `Radicle/src/schema/scalar.cpp:scalar_field_bytes` returns empty for a field past a short payload, which `set_record_scalar` reports as `subrecord_missing` with nothing changed. Bytes 3, 6, 7, 29-31 and any bytes past 32 are never written.
- `GRAS\UnitsFromWaterType` is capped at 7 because the xEdit enum has eight values. Measured over `Fallout4.esm`, `DLCCoast.esm` and `DLCNukaWorld.esm` (the only official masters with GRAS, 107 records, all DATA 32 bytes) the stored values are 0, 2, 6 and 7. The cap is a schema limit for edits, not a claim about the engine; the reader still returns any stored u32.
- `TREE\TrunkFlexibility` through `TREE\LeafFrequency` are twelve f32 at offsets 0..44 of `TREE\CNAM` in xEdit order. Float bounds are +-1e9 like the PROJ/EXPL/HAZD fields; `Radicle/src/schema/scalar.cpp:encode_scalar` already rejects NaN and infinities (`parse_float`) and a result that overflows f32, so no encoder change was needed.
- `TREE\Spring`, `Summer`, `Fall`, `Winter` and the same four `FLOR\` paths are u8 at 0..3 of `PFPC`. These are stored seasonal values; no runtime meaning is claimed (see `Radicle/docs/VEGETATION.md`).
- `Radicle/include/fo4/schema/scalar.hpp:ScalarDescriptor::payload_size` is an optional exact payload size for embedded fields, set from the JSON key `payload_size` by `Radicle/tools/schema_codegen.py:load_fields` (embedded only, a positive integer, at least offset plus storage width). It is 48 for `TREE\CNAM`, 4 for `PFPC` and 2 for `FLOR\FNAM`. `Radicle/src/schema/scalar.cpp:scalar_field_bytes` returns an empty span (field absent) when the payload size differs, exactly like an embedded field beyond a shorter payload, and does not throw. Reason: `PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp` turns any `ScalarError` into a failure of the whole record-table read and `Radicle/src/schema/preflight.cpp` reports it as an error, while the vegetation loader treats a non-48-byte CNAM as an opaque layout; `Radicle/src/environment/vegetation.cpp:decode_tree` leaves wind unset for it and `decode_flora` rejects a wrong-size PFPC/FNAM separately at decode time. So the grid shows a blank non-editable cell, preflight skips it, and `set_record_scalar` returns `subrecord_missing` with no byte changed (44/52-byte CNAM, 3/5-byte PFPC, 1/3-byte FNAM). The whole-payload wrong-width throw is unchanged.
- `FLOR\Flags` is registered as an embedded field at offset 0 of `FNAM` with `payload_size` 2, not as a whole-payload field. `Radicle/src/schema/scalar.cpp:scalar_descriptor` finds whole-payload fields by subrecord signature alone and `FNAM` means different things on other records, so a whole-payload registration would be returned for any FNAM. Embedded fields are skipped by that lookup and are only reachable by record plus path.
- Refusals (`ScalarError`, bytes untouched): wrong record type, duplicate subrecord, value out of range, unparsable value, NaN/infinity. Record absent gives `record_missing`; subrecord absent, beyond a short GRAS DATA, or of an unsupported payload size gives `subrecord_missing`. Nothing is inserted.
- `Radicle/src/c_api_writeback.cpp:radicle_plugin_set_record_scalar` takes a schema path and a decimal string. `updated` and `unchanged` map to OK; missing record and missing/short/unsupported-size subrecord map to NOT_FOUND with distinct `radicle_last_error` text; unknown path, null argument, invalid key and every `ScalarError` map to INVALID_ARGUMENT. `Radicle/bindings/csharp/Radicle.Interop/PluginFile.cs:SetScalar` returns false for NOT_FOUND and throws `RadicleException` otherwise; callers pass invariant-culture numbers.
- ABI 17 (`Radicle/include/fo4/c_api.h:RADICLE_ABI_VERSION`) is provisional: it sits on the PR #404 vegetation reader dependency and must be reassigned from current main before merging.
- Coverage: `Radicle/tests/test_vegetation_edit.cpp:VegetationEdit` (every path, unchanged, short DATA, refused layouts, compressed record, C ABI), `Radicle/bindings/csharp/Radicle.Interop.Tests/VegetationEditTests.cs`, and `Radicle/tests/test_vegetation_real.cpp:VegetationReal.EveryNewScalarPathEditsOfficialRecordsWithoutLosingData` over the official masters (skips without FO4_DATA_DIR).
- Not done: no ADD/REMOVE/CREATE of vegetation records or subrecords, no PFIG/SNAM link writes, no LTEX GNAM list edits, no MODL/OBND edits, and no claim about how the engine consumes any of these values.
