# Radicle semantic editor integration

## Shared field addressing

`PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp:RadiclePluginBackend::getRecordsGrid` and `RadiclePluginScalar.cpp:RadiclePluginBackend::setFieldValue` must consume the generated Radicle descriptors and `fo4::schema::resolve_field_slots`. Repeated field paths append `[index]` to the descriptor path; indices identify storage slots and must not be compacted when a slot is unavailable. String writes use `fo4::set_record_string`, numeric writes use the indexed `fo4::set_record_scalar`, and links retain target validation before using the indexed writer. Missing, malformed, localized or discriminator-inapplicable values remain unavailable. The original raw projection is retained for inspection.

## Acceptance scope

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:RadiclePluginBackend::describeElement` exposes schema subrecords at `Authoring\\SIG` and existing occurrences at `Authoring\\SIG[index]`. Capability discovery probes the existing native add/remove/create APIs on disposable plugin copies; React receives the resulting permissions and does not reproduce defaults, ordering, minimum counts or coupling. Mutations repeat the native checks under the existing write guard and stage only successful changes. `RadiclePluginLifecycle.cpp:RadiclePluginBackend::createRecord` selects generated-schema creation only for an explicit `schema: true` payload, preserving the existing typed creation payloads.

`PluginEditTool/web/src/RecordView.tsx:RecordView` loads context-menu capabilities in an effect keyed on `[menu]` only. A response from an earlier menu is dropped when a newer menu opens (`menuSeq`); changes to the record or plugin columns do not cancel it. `RecordContextMenu.tsx:RecordContextMenu` shows schema creation only with `canCreate`; `recordActions.ts:useRecordActions` submits the editor ID through explicit schema creation and refreshes the record and plugin views.

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:resolveElementPath` maps generated list count rows to their list descriptor for structural actions. `RadiclePluginBackend::describeElement` probes native null insertion to establish a valid empty-list anchor, retaining refusal for non-nullable lists and records without a proven boundary. Count values remain read-only.

`Radicle/src/schema/formlink_list_read.cpp:fo4::schema::record_formlink_list_values` keeps generated list decoding in Radicle. It validates through the existing list-size function and reads through the shared slot resolver, retaining stored order for per-subrecord and packed lists. `PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` exposes indexed links and read-only count rows without reproducing binary layouts in the adapter. This C++ addition does not add or change a C ABI export.

`PluginEditTool/native/src/plugin/RadiclePluginQueries.cpp:RadiclePluginBackend::getConflictMatrix` remains part of issue #434's semantic projection work. Completion requires semantic Record View rows, explicit raw inspection, shared grid addressing, strings/repeated/packed/variant/list mutation, schema-gated authoring controls, override alignment, and normal/AutoWeapon sound acceptance plus climate, water and vegetation regressions. Main at `c50ad4d5405e1571113019654b10e3d4a05ca0f1` contains the W0 infrastructure; pending family writers must be tested on their actual branches and must not be presented as landed capabilities.

## Explorer refresh

`PluginEditTool/web/src/Shell/ExplorerTree.tsx:ExplorerTree` caches each node's children in component state under a `Key:index` key that survives a refresh, so a plugin-list refresh left group counts such as `CLMT (1)` stale. Every refresh path replaces the plugin list through `setPlugins` in `PluginEditTool/web/src/Shell/useEnvironment.ts`, which hands each tree a new `node` object; that object identity is the refresh signal. A changed node drops collapsed children; an expanded node refetches through `PluginEditTool/web/src/Shell/ExplorerTree.tsx:ExplorerTree`, and the same object causes no fetch. Expanding a node always fetches, so children are not reused across collapse and expand.

The fetch effect in `ExplorerTree.tsx:ExplorerTree` stamps each request with a counter in `requests` and applies its result only while it is still the newest request, so a slow response from an earlier refresh cannot overwrite a newer one. State is set only inside the promise callbacks; the loading flag is raised by `toggle` on expand and by the render-time node-change check, because `react-hooks/set-state-in-effect` (eslint-plugin-react-hooks 7) also flags setState in any function the effect calls, even after an `await`. While a refetch is in flight the row shows the same `...` indicator as the first load. A refreshed node with `HasChildren` false renders no children, loading indicator or error (`shown`). Expanding always refetches. `eslint` on this file is clean; CI does not run the web lint or vitest, so the tests in `PluginEditTool/web/src/Shell/ExplorerTree.test.tsx` (stale-response and no-children cases) are local-only until it does.

## PluginEditTool/native/src/plugin/RadiclePluginMutation.cpp:RadiclePluginBackend::setField — EDID text encoding (GT-168)

EDID text is UTF-8 on the transport and Windows-1252 in the record. Radicle converts at the writer: `Radicle/src/plugin/mutation.cpp:stored_editor_id` (used by `set_record_editor_id`) and the typed creators in `Radicle/src/forms/` (`armor.cpp:encode_editor_id`, `cell.cpp`, `eyes.cpp`, `race.cpp`, `proj_expl_hazd.cpp`) convert UTF-8 and throw `FormIdError` for text Windows-1252 cannot represent. So `setField`, copy-as-new in `PluginEditTool/native/src/plugin/RadiclePluginMaintenance.cpp`, the typed creators in `PluginEditTool/native/src/plugin/RadiclePluginLifecycle.cpp:RadiclePluginBackend::createRecord` (CELL, EYES, LVSP, RACE, ARMO, ARMA) and the PROJ, EXPL and HAZD builders in `PluginEditTool/native/src/plugin/RadiclePluginProjExplHazd.cpp` pass the caller's UTF-8 straight to Radicle. Only schema create is pre-encoded, by `PluginEditTool/native/src/plugin/RadiclePluginSupport.hpp:encodeEditorId`, because `Radicle/src/plugin/subrecord_authoring.cpp:create_record` stores the bytes it is given. A refusal stays fail-closed: `FieldWriteFailed` for setField, `CopyAsNewFailed` for copy-as-new, `<Kind>CreateFailed` for typed creators (for example `EyesCreateFailed`) and `InvalidEditorId` for schema create, with nothing staged. This is stricter than xEdit, which encodes through the file's code page (`Core/wbInterface.pas:15695`, `GetBytes`; `:23867`, Windows-1252 at `93cc0bc5`) and does not refuse. It is a fail-closed choice: Radicle refuses text it cannot store exactly instead of writing a substituted character. The EDID readers decode with `fo4::text::windows1252_to_utf8` in `PluginEditTool/native/src/plugin/RadiclePluginSupport.hpp:editorId`, which the listing, lookup, copy and Cell readers all call. Tests: `PluginEditTool/native/tests/unit/RadiclePluginW0Tests.cpp` (EDID setField and typed EYES round trips and refusals), `RadiclePluginMaintenanceTests.cpp` (copy-as-new) and `RadiclePluginLifecycleTests.cpp` (create).

## Radicle/schema/fallout4/fields.json:PROJ\Flags — u16 storage (GT-168 follow-up)

PROJ DNAM (`wbStruct(DNAM, 'Data')` at xEdit Core/wbDefinitionsFO4.pas:7122 @93cc0bc5, inside `wbRecord(PROJ` at line 7115) starts with `Flags` as `itU16` at offset 0 (xEdit Core/wbDefinitionsFO4.pas:7123-7138 @93cc0bc5), followed by `Type` as `itU16` at offset 2 (xEdit Core/wbDefinitionsFO4.pas:7139-7147 @93cc0bc5). The create and decode paths split the same way: `Radicle/src/forms/proj_expl_hazd.cpp:encode_projectile_dnam_with` writes `ProjectileCreation::flags` and `ProjectileCreation::type` as u16 at +0 and +2, and `decode_projectile` reads them back. `type` defaults to 1 (Missile). `ProjectileCreation` is a C++ struct only; it is not in the C ABI or the C# views. Test: `Radicle/tests/test_proj_expl_hazd_creation.cpp:ProjExplHazdCreation.ProjectileFlagsAndTypeOccupySeparateLeadingWords`.

## Wrong-size vegetation payloads and PROJ Type (grid read tolerance)

`PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` treats a single-field `FormLinkFieldError` from `fo4::record_field_count` (payload size mismatch, as xEdit tolerates) as one unavailable `<opaque>` cell at the field path, so the record stays listed and the rest of the grid and conflict matrix still load. `Radicle/src/plugin/field_writer.cpp:set_record_formlink_field` keeps refusing the same slot, so writes still fail. Test: `PluginEditTool/native/tests/unit/RadiclePluginVegetationSemanticTests.cpp` (`Vegetation semantic grids list a flora with a wrong-size ingredient as unavailable`).

`PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` also treats an embedded scalar whose subrecord payload differs from its schema `payload_size` as one unavailable `<opaque>` cell at the field path. The check is per field: any subrecord with that signature and a different size makes the field unavailable. Covered fields are the four `PFPC` seasons on TREE and FLOR, `FLOR\Flags` (FNAM, 2) and `TREE\TrunkFlexibility` through `TREE\LeafFrequency` (CNAM, 48). Before this, `semanticFieldCells` left those cells empty and non-editable. The rest of the grid loads, and `Radicle/src/plugin/mutation.cpp:set_record_scalar` still refuses the slot (`subrecord_missing`, bytes unchanged). xEdit reads the same records without refusing them: TREE PFPC is `wbStruct(PFPC, 'Ingredient Production', ...)` at `source:xEdit Core/wbDefinitionsFO4.pas:12144-12149 @93cc0bc5` (not required), FLOR PFPC at `12191-12196` (required), FLOR FNAM `wbInteger(FNAM, 'Flags', itU16, ...)` at `12180-12186`, TREE CNAM `wbStruct(CNAM, 'Tree Data')` at `12151-12164`; the integer members report a size mismatch only as a check message (`source:xEdit Core/wbInterface.pas:TwbIntegerDef.Check` lines 12343-12345, enabled by `wbCheckExpectedBytes` at line 365). Test: `PluginEditTool/native/tests/unit/RadiclePluginVegetationSemanticTests.cpp` (`Vegetation semantic grids list wrong-size flora and tree payloads as unavailable`).

`PluginEditTool/native/src/plugin/RadiclePluginProjExplHazd.cpp:RadiclePluginBackend::createProjectileLocked` reads the payload key `type` into `ProjectileCreation::type` (u16, so 0..65535) the same way `flags` is read. No `PROJ\Type` row exists in `Radicle/schema/fallout4/fields.json`, so there is no path mapping for `validateProvidedScalars`. Test: `PluginEditTool/native/tests/unit/RadiclePluginProjFlagsTests.cpp:Native PROJ creation writes Type as its own u16 and reads it back`.

## PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells — malformed NPC_ PKID/PNAM payloads

A `per_subrecord` list element that is not exactly four bytes makes `Radicle/src/schema/formlink_lists.cpp:matching_positions` throw `FormLinkListError`, and the generated-list loop in `PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` lets it escape, so `PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp:RadiclePluginBackend::listRecordsSummary` fails the whole page with `FormLinkReadFailed` instead of one cell. That is kept deliberately: it is the same fail-closed policy the packed lists already follow (`PluginEditTool/native/tests/unit/RadiclePluginSoundSemanticTests.cpp`, `RadiclePluginVegetationSemanticTests.cpp` and `RadiclePluginW0Tests.cpp` pin it), and a malformed run reported as one `<opaque>` cell would read like a list that is merely unavailable. The single-cell `<opaque>` degradation stays limited to the single-field `FormLinkFieldError` case above. No shipped record is affected: 0 of the 3015 `Fallout4.esm` NPC_ records carry a PKID or PNAM payload that is not four bytes. Tests: `PluginEditTool/native/tests/unit/RadiclePluginSchemaGridTests.cpp` (`Malformed NPC_ package payload fails the page instead of blanking the list`, with `NPC_ package and head part lists reach the grid as indexed columns` pinning the healthy read of the same rows).
