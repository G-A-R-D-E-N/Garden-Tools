# Radicle semantic editor integration

## Shared field addressing

`PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp:RadiclePluginBackend::getRecordsGrid` and `RadiclePluginScalar.cpp:RadiclePluginBackend::setFieldValue` must consume the generated Radicle descriptors and `fo4::schema::resolve_field_slots`. Repeated field paths append `[index]` to the descriptor path; indices identify storage slots and must not be compacted when a slot is unavailable. String writes use `fo4::set_record_string`, numeric writes use the indexed `fo4::set_record_scalar`, and links retain target validation before using the indexed writer. Missing, malformed, localized or discriminator-inapplicable values remain unavailable. The original raw projection is retained for inspection.

## Acceptance scope

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:RadiclePluginBackend::describeElement` exposes schema subrecords at `Authoring\\SIG` and existing occurrences at `Authoring\\SIG[index]`. Capability discovery probes the existing native add/remove/create APIs on disposable plugin copies; React receives the resulting permissions and does not reproduce defaults, ordering, minimum counts or coupling. Mutations repeat the native checks under the existing write guard and stage only successful changes. `RadiclePluginLifecycle.cpp:RadiclePluginBackend::createRecord` selects generated-schema creation only for an explicit `schema: true` payload, preserving the existing typed creation payloads.

`PluginEditTool/web/src/RecordView.tsx:RecordView` cancels outdated context-menu capability responses when the menu, record or plugin columns change. `RecordContextMenu.tsx:RecordContextMenu` shows schema creation only with `canCreate`; `recordActions.ts:useRecordActions` submits the editor ID through explicit schema creation and refreshes the record and plugin views.

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:resolveElementPath` maps generated list count rows to their list descriptor for structural actions. `RadiclePluginBackend::describeElement` probes native null insertion to establish a valid empty-list anchor, retaining refusal for non-nullable lists and records without a proven boundary. Count values remain read-only.

`Radicle/src/schema/formlink_list_read.cpp:fo4::schema::record_formlink_list_values` keeps generated list decoding in Radicle. It validates through the existing list-size function and reads through the shared slot resolver, retaining stored order for per-subrecord and packed lists. `PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` exposes indexed links and read-only count rows without reproducing binary layouts in the adapter. This C++ addition does not add or change a C ABI export.

`PluginEditTool/native/src/plugin/RadiclePluginQueries.cpp:RadiclePluginBackend::getConflictMatrix` remains part of issue #434's semantic projection work. Completion requires semantic Record View rows, explicit raw inspection, shared grid addressing, strings/repeated/packed/variant/list mutation, schema-gated authoring controls, override alignment, and normal/AutoWeapon sound acceptance plus climate, water and vegetation regressions. Main at `c50ad4d5405e1571113019654b10e3d4a05ca0f1` contains the W0 infrastructure; pending family writers must be tested on their actual branches and must not be presented as landed capabilities.

## Native validation and protection

`PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` validates each descriptor through `fo4::record_field_count` before projecting slots, preserving the native writer's structural checks instead of duplicating family layouts. A separate checkout combining this adapter with sound PR #400 reproduced four malformed-read cases: AutoWeapon rate-count mismatch, oversized descriptor link, footstep count mismatch and an incomplete packed track (`build/sound-red-confirmed.log`). Reusing native validation and refusing misaligned slots passes all six fixture acceptance cases and 423 assertions (`build/sound-green.log`); official-master UI acceptance and the remaining family regressions are still outstanding.

`PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp:RadiclePluginBackend::getRecordsGrid` clamps all grid permissions to the existing plugin protection policy. `PluginEditTool/native/tests/unit/RadiclePluginReadApiTests.cpp` reproduces the protected editor-ID cell advertising editability (`build/protected-grid-red.log`), while native writes already refuse it. This applies to the typed grids and the generated semantic grid alike.
