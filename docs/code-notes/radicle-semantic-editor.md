# Radicle semantic editor integration

## Shared field addressing

`PluginEditTool/native/src/plugin/RadiclePluginReadApi.cpp:RadiclePluginBackend::getRecordsGrid` and `RadiclePluginScalar.cpp:RadiclePluginBackend::setFieldValue` must consume the generated Radicle descriptors and `fo4::schema::resolve_field_slots`. Repeated field paths append `[index]` to the descriptor path; indices identify storage slots and must not be compacted when a slot is unavailable. String writes use `fo4::set_record_string`, numeric writes use the indexed `fo4::set_record_scalar`, and links retain target validation before using the indexed writer. Missing, malformed, localized or discriminator-inapplicable values remain unavailable. The original raw projection is retained for inspection.

## Acceptance scope

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:RadiclePluginBackend::describeElement` exposes schema subrecords at `Authoring\\SIG` and existing occurrences at `Authoring\\SIG[index]`. Capability discovery probes the existing native add/remove/create APIs on disposable plugin copies; React receives the resulting permissions and does not reproduce defaults, ordering, minimum counts or coupling. Mutations repeat the native checks under the existing write guard and stage only successful changes. `RadiclePluginLifecycle.cpp:RadiclePluginBackend::createRecord` selects generated-schema creation only for an explicit `schema: true` payload, preserving the existing typed creation payloads.

`PluginEditTool/web/src/RecordView.tsx:RecordView` cancels outdated context-menu capability responses when the menu, record or plugin columns change. `RecordContextMenu.tsx:RecordContextMenu` shows schema creation only with `canCreate`; `recordActions.ts:useRecordActions` submits the editor ID through explicit schema creation and refreshes the record and plugin views.

`PluginEditTool/native/src/plugin/RadiclePluginElement.cpp:resolveElementPath` maps generated list count rows to their list descriptor for structural actions. `RadiclePluginBackend::describeElement` probes native null insertion to establish a valid empty-list anchor, retaining refusal for non-nullable lists and records without a proven boundary. Count values remain read-only.

`Radicle/src/schema/formlink_list_read.cpp:fo4::schema::record_formlink_list_values` keeps generated list decoding in Radicle. It validates through the existing list-size function and reads through the shared slot resolver, retaining stored order for per-subrecord and packed lists. `PluginEditTool/native/src/plugin/RadiclePluginFields.cpp:semanticFieldCells` exposes indexed links and read-only count rows without reproducing binary layouts in the adapter. This C++ addition does not add or change a C ABI export.

`PluginEditTool/native/src/plugin/RadiclePluginQueries.cpp:RadiclePluginBackend::getConflictMatrix` remains part of issue #434's semantic projection work. Completion requires semantic Record View rows, explicit raw inspection, shared grid addressing, strings/repeated/packed/variant/list mutation, schema-gated authoring controls, override alignment, and normal/AutoWeapon sound acceptance plus climate, water and vegetation regressions. ## PluginEditTool/native/src/plugin/RadiclePluginMutation.cpp:RadiclePluginBackend::setField — EDID text encoding (GT-168)

EDID text is UTF-8 on the transport and Windows-1252 in the record. Core writers store the bytes they are given (`Radicle/src/plugin/mutation.cpp:set_record_editor_id`, and the typed creators in `Radicle/src/forms/`), so every PluginEditTool write path converts first with `PluginEditTool/native/src/plugin/RadiclePluginSupport.hpp:encodeEditorId` or `encodeOptionalEditorId`. Text that cannot be encoded returns `InvalidEditorId` before anything is created or staged. This is stricter than xEdit, which encodes through the file's code page (`Core/wbInterface.pas:15695`, `GetBytes`; `:23867`, Windows-1252 at `93cc0bc5`) and does not refuse. It is a fail-closed choice: Radicle refuses text it cannot store exactly instead of writing a substituted character. The paths are `setField`, copy-as-new in `PluginEditTool/native/src/plugin/RadiclePluginMaintenance.cpp`, the typed creators in `PluginEditTool/native/src/plugin/RadiclePluginLifecycle.cpp:RadiclePluginBackend::createRecord` (schema, CELL, EYES, LVSP, RACE, ARMO, ARMA) and the PROJ, EXPL and HAZD builders in `PluginEditTool/native/src/plugin/RadiclePluginProjExplHazd.cpp`. The EDID readers decode with `fo4::text::windows1252_to_utf8`: `RadiclePluginSupport.hpp:editorId`, `RadiclePluginReadApi.cpp:editorId`, `RadiclePluginAnalysis.cpp:editorId`, `RadiclePluginOverridePatch.cpp:editorId`, `RadiclePluginMutation.cpp:editorId` and `RadiclePluginMaintenance.cpp:recordEditorId`. Test: `PluginEditTool/native/tests/unit/RadiclePluginW0Tests.cpp` (typed EYES round trip).

## Radicle/schema/fallout4/fields.json:PROJ\Flags — u16 storage (GT-168 follow-up)

PROJ DNAM (`source:xEdit Core/wbDefinitionsFO4.pas:7122-7139 @93cc0bc5`, the `wbStruct(DNAM, 'Data')` for `wbRecord(PROJ` at line 7115) starts with `Flags` as `itU16` at offset 0, followed by `Type` as `itU16` at offset 2. The row was u32, so a Flags write also rewrote the Type bytes. The row is now u16 with maximum 65535, and `Radicle/include/fo4/schema/generated_scalar_fields.inc` carries the same change because the generator output is checked by `radicle_schema_check`. Test: `PluginEditTool/native/tests/unit/RadiclePluginProjFlagsTests.cpp:Native PROJ Flags SetField writes its u16 and leaves the embedded Type bytes`.

The create and decode paths split the same way: `Radicle/src/forms/proj_expl_hazd.cpp:encode_projectile_dnam_with` writes `ProjectileCreation::flags` and `ProjectileCreation::type` as u16 at +0 and +2, and `decode_projectile` reads them back. `type` defaults to 1 (Missile). `ProjectileCreation` is a C++ struct only; it is not in the C ABI or the C# views. Test: `Radicle/tests/test_proj_expl_hazd_creation.cpp:ProjExplHazdCreation.ProjectileFlagsAndTypeAreSeparateSixteenBitWords`.
